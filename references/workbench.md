# 工作台入口、任务与验收

## 选择入口

只在实际制作、重做或继续视频时进入此流程。规则迭代、代码维护、版本检查不启动页面。已由队列派发的单视频子 Agent 按自己的 PROMPT 执行，不重复启动入口。

工作台随当前安装的 skill 分发，不复制进每个任务的冻结引擎。若从冻结引擎恢复，使用宿主登记的当前安装 skill 启动工作台；渲染仍使用原冻结引擎，不能从冻结快照启动网页入口。

所有路径基于当前安装的 skill 实际目录，PROJECT 是用户项目根，不能以 skill 安装目录作为项目根。独立制作与宿主模式共用同一个本地队列和制作引擎。

### 工作区与交付目录

从命令行直接运行入口时，默认以当前目录为工作区。可用 `--workspace DIRECTORY` 改到另一块磁盘，也可在「设置 → 工作区」填写路径。相对路径按项目目录解析，留空恢复启动目录。用项目启动器打开时，默认从原项目目录工作。项目内的配置、机构库和队列继续由原项目管理。

新任务在创建时记录工作区。单条和多条统一采用 `工作区/批次_ID/视频_01/工程`，成片、封面与发布文案存放在对应视频的 `交付产物` 子目录。更改设置只影响随后创建的批次，旧任务沿记录路径制作、恢复和下载。

页面点击「下载发布包」才组装 ZIP，下载完成或断开后释放临时包。离线交付命令指明需要本地 ZIP 时，把生成的发布包放入该视频的交付目录。作品验收或删除任务后，工作区里的交付产物继续可用。

### 本机工作台

```bash
rtk python3 SKILL/scripts/workbench.py --project PROJECT
```

Windows 双击 `scripts/workbench/打开工作台.cmd`，找不到已有项目时输入项目文件夹路径。也可在 PowerShell 中给它传入 `--project "D:\养老视频项目"`。Windows 启动器查找 Python 3.11 或更高版本。

打开「设置 → 制作模型」。先选平台，工作台会填入支持看图和 JSON 输出的默认模型及官方地址。火山方舟的地址为 `https://ark.cn-beijing.volces.com/api/v3`，模型 ID 可换成方舟接入点 ID。DeepSeek 官方地址为 `https://api.deepseek.com`。填写相应平台的推理 API Key，可点「测试模型连接」检查图像识别和 JSON 输出，然后保存。连接测试仅发送合成图，生产中的模型用量由所选平台的 Key 对应账号结算。

接入其他服务时，选「自定义 · OpenAI 兼容」，填写该服务的 Base URL、模型 ID 和 API Key。工作台按 OpenAI Chat Completions 格式请求 `/chat/completions`，用 `Authorization: Bearer` 鉴权。远程地址使用 HTTPS，本机服务可用 HTTP。保存的 Key 与该地址绑定，换地址时填写对应的 Key。默认使用 JSON 模式，遇到服务不接受该参数时，可在「高级选项 → JSON 输出方式」选择「用提示词要求 JSON」，再点「测试模型连接」。测试通过说明该模型能识别合成图片并返回工作台可读取的 JSON 对象。

「设置 → 制作模型 → 单条制作时限（分钟）」默认为 60，可填写正整数。每条视频从接单开始计时，自动重试和等待服务回传计入时限。改动应用于之后接单的视频。超时停止当前条，保留已有工程文件和数字人任务记录，确认执行结束后继续处理下一条。

模型连接暂时失败、限流、服务短暂异常或返回不完整 JSON 时，独立制作最多自动重试两次。素材整理到达步骤时限可自动重试一次。数字人生成仍按已有任务编号查询。

独立制作自动生成的口播字幕由排版引擎按字宽和实际发音时间断行。片中标题条超过字数限制时，单独修正标题条，再按原流程核对事实和内容。

新建 60 秒任务时，同批共用已核实的事实，每篇单独写口播。字数依人物的历史配音估算，无可用参考时先按 210–230 个可读字。工作台核对字数、销售带看口吻和同批正文重复；配置的结尾钩子和必须保留的名称独立于重复检查。正文相似度达到 90% 时局部改写。定稿后按正文制作分镜、封面和发布文案。

一分钟任务实测含片头留白为 55–70 秒时使用原速。少于 55 秒按实测语速补稿。超过 70 秒最多以 1.15 倍保音高加速，字幕和数字人使用加速后的音频。仍超时则回到改稿。其他目标时长沿用前后 5 秒的验收范围。

同页可填写和分别测试语音 API Key、数字人 AK/SK 和 TOS。语音测试生成一句短音频，数字人和 TOS 使用查询请求。数字人测试通过查询当前连接的真实任务验证权限，工作台会在本项目内保留最近一次查询成功的任务编号。首次没有任务记录时，可在完成制作后测试。已有凭据留空即继续使用。使用 OmniHuman 时，如果服务拒绝 tmpfile 域名，可改用已授权的 TOS 桶。

在「新建制作」填写要求。缺少制作配置时，按主按钮提示补齐，草稿会保留。多人或多条批次先完成统一策划，再逐条制作；队列只给制作项编号。Python 本机服务接单，调用模型完成策划和文画审核，调用配置的媒体服务，最后用本机 FFmpeg 和 Chromium 渲染并输出视频、封面和发布包。模型只接收制作所需的文本和抽帧，无权执行本机命令。关闭浏览器或启动器打开的 Terminal 窗口，服务仍会运行。要停止本地监听，请在「设置 → 本地工作台」点「退出工作台」。排队、制作、清理和音色复刻期间会提示稍后退出。机器重启后从项目启动器重新打开，已有任务按原检查点恢复。需要补充时，在任务页提交一次答复即可。

重复双击项目启动器会打开当前项目已有的工作台页面。若同项目服务正在启动、退出或暂时无响应，启动器会提示稍后再试。不同项目可各自运行。健康服务检测到代码更新时在空闲后切换。有未回收的执行者时打开现有页面并返回 deferredUpgrade。只绑定 127.0.0.1，页面凭据仍留项目私有配置。macOS 同时在项目根留下 `打开视频工作台.command`，以后双击即可独立打开，不需要 Agent 对话；它固定项目与安装入口，复用服务并遵守执行锁保护。不同浏览器不共享会话，首次使用完整 URL 建立本地会话；只输入裸端口地址时显示连接指引，不暴露访问令牌或取消认证。本地工作台在配置齐全后自动接单。把返回的完整 URL 提供给用户。启动脚本通过系统默认浏览器打开。若自动打开失败，提供项目启动器和完整 URL，让用户在本机浏览器打开，不回退到 Agent 内置页面。工作台页面检查也使用用户电脑的本地浏览器；无页面模式和维护模式仍不自动打开浏览器。

### 可选的 Codex 协调

需要使用 Codex 主对话制作时，显式运行：

```bash
rtk python3 SKILL/scripts/workbench.py --project PROJECT --host codex
```

主对话随后读取 `scripts/workbench/AGENT.md`，通过[原生文件通道](workbench-channel.md)和当前宿主原生子 Agent 工具协调；新批次先做[整批统一策划](batch-planning.md)，逐视频用连续执行器推进。没有原生子 Agent 能力时说明具体限制并保留排队任务，不冒称已开始。长素材、稿件、日志留在单条工程和子 Agent，主对话只收短结果。

## 从对话提交制作

用户已经给足资料时，不要求其在页面再填一遍。智能体把本次请求写入项目 `.montage/workbench/submissions/` 下的新 JSON，再执行入口 `--request FILE`。同一次请求重试沿用该文件和 `--invocation ID`，新请求用新 ID；脚本原子记录批次，避免重复入队。

请求常用字段：`source`（机构目录）或 `institutionId`、`institutionName`、`person`、`count`、`requirements`、`facts`、`music`、`videoPreferences`。多人物用 `people:[{"id":"人物ID","count":2}]`；总数和各人物顺序由脚本展开。人物 ID 读项目配置，不猜测。source 首次导入机构资料库，任务固定版本；同机构后续更新不改变旧任务。

缺少配置时先打开页面，引导用户补缺，不丢弃本次请求，也不自行填入虚假服务凭据。

## 用户明确不要页面

用户说“本地执行这个视频任务”“直接执行”“不用页面”或“不要 HTTP”时，按无需页面处理，不要求用户重复说明，使用：

```bash
rtk python3 SKILL/scripts/workbench.py --project PROJECT --host workbuddy --mode direct --request FILE
```

此模式不启动 HTTP、不打开浏览器，仍在同一本地 FIFO 保存状态、按原提交顺序执行；已有工作台服务不强制关闭。当前宿主按同一 AGENT.md 协调与回传，用户可在对话查看真实阶段，之后打开页面仍能看到记录。`--mode maintenance` 不启动服务、任务或监听，仅供明确的维护入口。

执行者已回收后，运行 `python3 SKILL/scripts/workbench/deliver.py --project PROJECT TASK_ID` 获取 MP4、PNG、三文件发布 ZIP 的实际路径，直接交付脚本返回的发布包；不把引擎内部含编辑 HTML 的包另行交给用户。此命令也不启动 HTTP。

## 状态

草稿 → 排队中 → 制作中 → 待验收 → 已验收。待补充、失败或中断暂停在原序号；取消需要确认执行者退出。制作完成的队列终态与用户验收分开记录，验收不会占用制作锁，也不会更改领取顺序。列表、详情都有验收入口，部分完成且其余已取消时可验收已经完成的条目。

工作台任务只需在任务页答复一次。页面会显示答复已保存、正在等待旧执行者结束或等待重新接单。本机工作台按原序继续。使用 Codex 协调时，由主对话继续接单。

## 验收与清理

用户先预览成品，在列表或详情点击“验收成品”即记录用户验收并提交后台清理，不再弹窗或二次确认。页面显示后台清理状态，成品可继续查看和下载；清理失败保留已验收状态及成品，提供“重试清理”。服务重启后恢复未完成清理，不因旧进程尚活着而重复执行。制作 Agent 不能代替用户点击验收。

只清理任务自己创建的工程、对应封面编辑缓存，以及能按不可变素材 ID 恢复的任务素材副本。保留全部已完成版本的 MP4、PNG、发布文案及最少计划、核验与验收记录。新工作区任务按需下载发布 ZIP；旧任务保留已有发布包。原始机构资料库、人物、配置、认可基线、其他任务与共享引擎不属于清理范围。路径或成品哈希有变化、执行者未回收、重做仍引用工程时拒绝清理。

验收后中间配音、数字人和渲染资产已删除；再改口播时新建任务，从原资料版本完整重做，不伪称还能无成本恢复。封面自包含数据仍保留，可继续编辑首帧；成功更新后重新待验收。验收本任务不等于更新项目的通用样式基线。

无页面模式或用户在对话要求验收时：

```bash
rtk python3 SKILL/scripts/workbench/accept.py --project PROJECT preview TASK_ID
rtk python3 SKILL/scripts/workbench/accept.py --project PROJECT accept TASK_ID --token PREVIEW_TOKEN --confirmed
```

先呈现真实预览；只有用户明确验收并接受清理范围后才用 `--confirmed`。预览令牌绑定本次文件清单，变化后必须重新预览。清理中断不撤销用户的验收，成品仍保留；可从页面重试清理。CLI 的显式预览令牌仍校验文件变化。

## 进度与内容管理

阶段进度、回传间隔、删除任务保留成品与批量管理见[工作台进度与管理](workbench-management.md)。删除任务会先独立保留成品，再清理任务数据并移除任务记录；验收则保留任务状态。两者均保护原始文件与认可基线。
